# Python과 TypeScript 비교

| Python | TypeScript 비유 | 코드에서 볼 곳 |
| --- | --- | --- |
| `dict`, `list`, `set` | Record/Map, Array, Set | 파서 상세값, 기록 목록, visited |
| `None` | null | 시각·사용자 미상 |
| `@dataclass` | 필드가 있는 interface + 생성자 | core/models.py |
| `yield event` | generator의 yield | parser/*.py |
| `with resource:` | using 또는 try/finally | 파일·SQLite·이미지 자원 정리 |
| `Path` | node:path에 파일 I/O를 더한 객체 | 입력·출력 경로 |
| `struct.unpack_from` | DataView.getUint32(offset, true) | 이진 포맷 |
| `bytes`, `bytearray` | 읽기 전용/수정 가능한 Uint8Array | 증거 파싱·합성 fixture |
| Protocol | 구조적 interface | Parser/Collector 계약 |
| `python -m unittest discover -s tests` | 테스트 러너 | 전체 회귀 검사 |

## 제너레이터와 오류

파서의 `parse(path)`는 `yield ForensicEvent(...)`를 반복합니다. 소비자는 for 루프로 받습니다. 함수 안에 yield가 있으면 호출 자체는 아직 읽기를 수행하지 않습니다. 범위를 검사한 뒤 `self.error(...)`로 진단을 남기고 계속할 수 있습니다. 예외를 빈 except로 숨기면 손상을 성공처럼 보이게 하므로 피합니다.

## ctypes Windows API

`collector/windows.py`는 운영체제가 제공하는 함수를 직접 바인딩합니다. 자체 DLL을 빌드하는 단계가 없습니다. HANDLE은 포인터 크기이므로 `argtypes`와 `restype`를 지정해 64비트 값이 잘리지 않게 합니다. 실패의 GetLastError와 핸들 정리를 함께 확인하세요. `CreateFileW`·`ReadFile` 공유 읽기와 `RegSaveKeyExW`·`EvtExportLog`가 주요 경로입니다.

```python
# 설명용: 실제 호출은 collector/windows.py의 타입·오류 처리를 읽으세요.
import ctypes
from ctypes import wintypes
handle_type = wintypes.HANDLE
buffer = ctypes.create_string_buffer(4096)
```

`ctypes.byref(value)`는 출력 인자의 주소를 넘깁니다. 이 학습 자료의 데모는 해당 Windows API를 호출하지 않으며 struct와 sqlite3만으로 가짜 자료를 만듭니다.
