# 포렌식·Windows·바이너리 기초

## 기록과 해석

아티팩트는 운영체제·프로그램이 남긴 기록입니다. 파일이 있었다는 사실, 자동 실행에 등록됐다는 사실, 실제 실행했다는 사실은 서로 다른 해석입니다. Log Hunter는 입력을 읽기 전용으로 분석하며 기록 속 명령을 실행하지 않습니다. 분석 전후 SHA-256은 입력 바이트가 바뀌었는지 확인하는 값입니다.

`Evidence`는 입력 위치·해시·수집 방법을, `ForensicEvent`는 기록 종류·출처·동작·시각·SID·대상·상세값을 담습니다. `ParserError`는 읽지 못한 위치와 이유를 남깁니다. 일부 손상이 있어도 가능한 다음 기록을 처리합니다.

## Windows 기록

레지스트리 REGF는 키/값/셀로 구성됩니다. NTUSER.DAT는 사용자별, SYSTEM·SOFTWARE는 시스템별 정보입니다. SID는 사용자 이름과 다른 식별자이며 예제는 `S-1-5-21-1000-2000-3000-1001`만 씁니다. LOG1/LOG2 복구는 원본을 쓰지 않고 검증된 변경을 임시 사본에 적용합니다.

NTFS는 MFT 레코드, 파일명 속성, 데이터런으로 파일을 찾습니다. 이미지 안 경로와 분석 PC의 추출 경로는 다르므로 manifest가 연결을 보존합니다. raw/dd·E01·고정 VHD, MBR/GPT와 NTFS를 읽으며 동적 VHD/VHDX·압축·암호화의 미지원 범위는 루트 README를 확인합니다.

브라우저 SQLite의 WAL에는 DB 본체에 아직 반영되지 않은 행이 있을 수 있습니다. 파이프라인은 DB와 보조 파일을 임시 폴더로 복사해 병합하고 원본 옆에 복구 파일을 만들지 않습니다.

## 시각과 불확실성

FILETIME은 1601년부터 100나노초 단위입니다. Chromium 시각은 같은 기준의 마이크로초입니다. 예약 작업의 RegistrationInfo/Date는 작성자가 지정할 수 있는 메타데이터입니다. NetworkList SYSTEMTIME에는 시간대가 없으므로 확인된 오프셋 없이 UTC로 만들지 않습니다. 입력 사본의 파일 mtime도 대상 PC의 실행 시각이 아닙니다. `timestamp=None`, `time_field=None`은 이런 미상을 표현합니다.

## 수집과 직접 읽기

Windows API를 ctypes로 호출해 공유 읽기·하이브 저장·로그 내보내기를 합니다. 잠긴 NTFS 파일은 관리자 권한으로 볼륨을 직접 읽을 수 있습니다. 현재 수집은 VSS 스냅샷을 생성하지 않습니다. 실행 중인 파일을 읽는 동안 내용이 바뀔 수 있어 `point_in_time_consistent: false`로 표시합니다. 이 예제는 실제 PC 수집이나 드라이브 읽기를 실행하지 않습니다.

## 바이트 읽기

`struct.unpack_from("<I", data, offset)`는 오프셋에서 4바이트 unsigned little-endian 수를 읽습니다. `<Q`는 8바이트입니다. UTF-16LE 문자의 종료 검사는 2바이트 경계에서 해야 하며 바이너리 PIDL은 문자열이 아닙니다. 읽기 전에 offset+length가 입력 범위를 넘지 않는지 검사하고, 셀·디렉터리 순환에는 visited 집합과 깊이 상한이 필요합니다.
