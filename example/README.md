# Log Hunter 학습 자료

Python 3.11 이상, 런타임 패키지 의존성 없이 동작하는 현재 구현의 학습용 설명입니다. 실행 중 PC의 실제 자료는 사용하지 않습니다.

## 시작하기

1. [시각 가이드](index.html)에서 일곱 구조도를 봅니다.
2. [기초 개념](docs/01_기초개념.md)과 [Python·TS 비교](docs/02_TS개발자를_위한_치트시트.md)를 읽습니다.
3. 저장소 루트에서 `python example/samples/demo.py`를 실행하고 [합성 보고서](samples/output/report.html)를 엽니다.
4. [파일별 가이드](docs/03_파일별_가이드.md)와 [실습](docs/04_실습_가이드.md)으로 코드를 따라갑니다.

## 구조

- `annotated/log_hunter/`: 현재 원본 Python 모듈의 해설판. `# ▶`로 시작하는 줄은 학습 해설입니다. 원본의 실행 코드·문자열·docstring은 그대로 보존합니다.
- `images/`: 구조도 7장의 SVG 원본과 `png/` 미리보기.
- `samples/demo.py`: 합성 바이너리·브라우저 DB를 만들고 실제 파이프라인으로 분석하는 생성기.
- `samples/evidence/`, `samples/output/`: 생성기로 재현 가능한 가짜 입력과 결과. 실제 PC에서 복사한 파일이 아닙니다.

## 코드 동일성

저장소 루트에서 `python tools/check_annotated.py`를 실행합니다. 원본과 해설판의 파일 집합 및 Python 토큰을 비교하며 주석·빈 줄만 무시합니다. 문자열/docstring·인덴트·실행식이 달라지면 실패합니다. 새 모듈도 해설판에 빠짐없이 있어야 합니다.

## 현재 흐름

입력 → 자동 인식 또는 지정 종류 → 이미지/이 PC의 NTFS 추출(해당할 때) → 해시 확인 → 임시 사본 복구 → 형식별 파서 → 공통 기록 → 시간순 정렬·관계 후보 → SQLite·JSON·CSV·Bodyfile·HTML.

수집은 Python ctypes가 Windows API를 직접 호출합니다. 공유 읽기·하이브 저장·이벤트 로그 내보내기와 직접 NTFS 읽기를 사용합니다. 자체 C 빌드나 별도 수집 DLL은 필요하지 않습니다. 스냅샷을 만들지 않으며 실행 중 원본은 `point_in_time_consistent: false`입니다. 수집·관리자 직접 분석은 Windows 전용이고, 오프라인 분석은 순수 Python입니다.

GUI는 데이터 출처·찾은 기록·분석 결과·사용자 계정 트리와 기록 정보를 표시합니다. 디스크 이미지의 폴더·파일 목록 및 텍스트/16진수 콘텐츠 뷰어도 있습니다. 이 학습 데모는 GUI나 관리자 수집을 자동 실행하지 않습니다.

## 합성 자료와 한계

가짜 사용자 alice, 문서용 example.com, 고정 SID와 날짜만 사용합니다. 출력의 입력 위치는 `C:\Evidence\synthetic` 기준으로 바꿉니다. 수집 시각·보고서 생성 시각은 고정, 처리 시간은 0으로 기록하므로 데모 결과를 성능 측정에 쓰면 안 됩니다. 원본 증거는 생성기 안의 struct/SQLite 구문으로부터 조립합니다.

샘플의 누락된 Run/RunOnce 키는 정보 진단 7개로 표시됩니다. 실제 손상이나 권한 오류를 숨기는 것이 아닙니다. 시각이 없는 명령 이력은 미상으로 남고 이름이 같은 기록은 실행 확정으로 단정하지 않습니다. 데모는 evidence/output 두 하위 폴더를 재생성하므로 개인 파일을 그곳에 넣지 마세요.

지원 범위와 설치는 [루트 README](../README.md)가 기준입니다. PNG 갱신 상태와 직접 확인하지 못한 화면은 PR 검증 항목에 기록합니다.
