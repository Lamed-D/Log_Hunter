# 트리 보기

GUI 왼쪽에 탐색 트리가 있습니다. 노드를 누르면 오른쪽
타임라인이 그 범위로 좁혀지고, 아래 **기록 정보** 창에 선택한 기록이 항목/값 트리로 보입니다.

## 화면 구성

```text
┌ 탐색 트리 ─────────────────────┬ 타임라인 | 처리 결과/오류 | 연관 분석 | 증거 파일 | 통계 ┐
│ 데이터 출처                     │  기록 종류 | 시각 | 무슨 일 | 파일/프로그램 ...            │
│  └ case.E01                     │  ...                                                    │
│     └ 볼륨 0                    │                                                         │
│        └ Windows\System32\...   ├ 기록 정보 | 원본 JSON ────────────────────────────────┤
│ 찾은 기록                       │  항목            값                                     │
│  ├ 실행한 프로그램              │  기록 종류       최근 실행한 프로그램                   │
│  ├ 최근 문서                    │  원본 파일       [case.E01] 볼륨 0\Windows\...\SYSTEM   │
│  └ ...                          │  └ 세부 정보     (펼치면 하위 값)                        │
│ 분석 결과                       │                                                         │
│ 사용자 계정                     │                                                         │
└─────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

## 트리 노드

| 루트 | 내용 | 클릭하면 |
| --- | --- | --- |
| 데이터 출처 | 이미지/이 PC → 볼륨(파일 시스템·크기·시작 위치) → **이미지 안의 모든 폴더·파일**(펼칠 때 읽음). 직접 추가한 파일은 그 경로대로 | 그 폴더·파일에서 나온 기록만 타임라인에 표시. 파일을 고르면 아래 파일 정보·16진수·텍스트 탭에 내용 표시 |
| 찾은 기록 | 아래 분류표. 기록이 있는 분류만 표시 | 해당 종류만 표시 |
| 분석 결과 | 연관 관계(유형별), 처리 오류·경고(심각도별) | 연관 분석 / 처리 결과 탭으로 이동해 해당 항목만 표시 |
| 사용자 계정 | SID별 기록 수. 하이브에서 찾은 이름 > 잘 알려진 계정 이름(예: 시스템 (SYSTEM)) 순으로 `이름 — SID`, 시스템·서비스 계정은 회색 | 그 사용자의 기록만 표시 |
| 분석자 태그 | 분석자가 붙인 색별(빨강·노랑·초록) › 하위 분류별 기록 수와 메모 있음, 태그한 파일 수 | 그 태그의 기록만 표시 / 태그한 파일을 파일 목록에 표시 |

트리 위에는 이름으로 찾기(Enter로 다음 항목), ◀ / ▶(Alt+← / →) 선택 기록 이동, 고른 노드의 경로 표시가 있고,
오른쪽 클릭으로 모두 펼치기 / 모두 접기 / 경로 복사 / 이름 복사를 합니다.

괄호 안 숫자는 기록 수입니다(분석 결과는 관계·오류 수). 트리 선택은 위쪽 검색·기록 종류·날짜·상태
필터와 함께 적용되며, 현재 범위는 통계 줄 오른쪽 `보기: ...`에 표시됩니다.

## 이미지 안 파일 탐색

- 이미지를 열면 추출·분석을 기다리지 않고 바로 이미지 → 볼륨 노드가 생깁니다. 분석이 끝나 트리를 다시 그릴 때
  펼쳐 둔 폴더와 선택한 노드는 그대로 유지됩니다(한 번 읽은 폴더 목록은 다시 읽지 않음).
- 폴더(또는 볼륨)를 고르면 **파일 목록** 탭: 이름 / 종류 / 크기 / 수정·생성·접근·MFT 변경 시각 / 상태 / 기록 수.
  시각과 상태는 보이는 페이지의 파일만 MFT에서 읽습니다(큰 폴더에서도 빠름). 정렬, 이름 검색, 2,000개 단위 페이지.
  폴더 행 더블클릭 = 트리에서 그 폴더로 이동, "이 폴더의 기록 보기" = 타임라인을 그 폴더 범위로.
- 오른쪽 클릭: **파일로 저장**(새 파일만 만들고 덮어쓰지 않음, SHA-256 표시, 같은 폴더에 `.log-hunter.json`으로
  이미지·볼륨·이미지 안 경로·MFT 번호·해시 기록), **이미지 안 경로 복사**.
- 볼륨 노드를 펼치면 그 NTFS 폴더를 이미지에서 바로 읽습니다(복사하지 않음, 읽기 전용). 폴더마다 펼칠 때 한 번 읽고,
  읽기는 작업 스레드 하나에서 해서 화면이 멈추지 않습니다.
- 폴더 이름 옆 숫자는 그 아래에서 나온 기록 수입니다. 기록이 없는 폴더·파일은 숫자를 붙이지 않습니다.
- 한 폴더에 2,000개가 넘으면 앞의 2,000개만 보이고 "… 외 N개"로 알려 줍니다.
- NTFS가 아닌 볼륨(BitLocker 암호화, FAT 등)은 펼치지 않습니다.

## 파일 보기

트리 루트 **파일 보기** → 종류별(그림·동영상·음성·문서·압축 파일·실행 파일·스크립트, 확장자 기준) / 삭제된 파일
(MFT 레코드가 "사용 안 함"인 파일) / 크기별(50MB~200MB, 200MB~1GB, 1GB 이상).
처음 고를 때 `$MFT`를 한 번 처음부터 끝까지 읽습니다(작업 스레드, 진행 표시, "찾기 취소"). 분류마다 10,000개까지 보여 주고
전체 개수는 함께 알려 줍니다. 삭제된 파일의 경로는 부모 폴더 기록으로 이어 붙이며, 부모가 없어진 부분은 `?`로 표시합니다.
삭제된 파일의 내용은 다른 파일로 덮어써졌을 수 있다고 파일 정보에 안내합니다. 크기 분류는 MFT에 적힌 크기 기준입니다.

## 아래 콘텐츠 뷰어

| 탭 | 내용 |
| --- | --- |
| 기록 정보 | 선택한 기록의 항목/값 트리 |
| 파일 정보 | 이미지·볼륨·이미지 안 경로, MFT 번호·순번, 사용 중/삭제, 크기, 생성·수정·접근·MFT 변경(UTC), SHA-256 |
| 16진수 | 4KB 페이지, 이전/다음 |
| 텍스트 | 처음 1MB에서 4글자 이상 ASCII·UTF-16 문자열(오프셋 포함) |
| 원본 JSON | 기록 전체 |

기록을 고르면 그 기록이 나온 파일을, 트리에서 파일을 고르면 그 파일을 보여 줍니다. 이미지에서 꺼낸 사본의 경우,
사본 자체의 수정 시각(꺼낸 시각)은 파일의 시각으로 보여 주지 않고 이미지에 기록된 시각만 보여 줍니다.

## 분류별 결과 표

트리에서 한 분류(예: 실행한 프로그램, 휴지통)를 고르면 표의 열이 그 분류에 맞게 바뀝니다
(`log_hunter/ui/columns.py`). 예: 실행한 프로그램 = 프로그램 / 사용자 / 시각 / 시각의 의미 / 출처 파일 / 설명,
휴지통 = 원래 위치 / 크기 / 사용자 / 시각 / … 여러 분류가 섞이면 기본 타임라인 열로 돌아갑니다.
"표를 CSV로 저장"은 필터·검색에 맞는 모든 행을 표의 열·순서 그대로 저장합니다(수식 주입 방지 적용).
타임라인 표에는 한 번에 5,000행씩만 넣고(◀ 이전 / 다음 ▶), 열 제목 정렬은 모든 행에 적용됩니다.
연관 분석 탭에서 행을 두 번 누르면 그 관계에 들어 있는 기록만 타임라인에 보입니다. 후보가 많아 묶어 둔 관계는
포함 기록 수·후보 쌍 수와 "모든 쌍이 관계인 것은 아님"을 함께 보여 줍니다.

### USB 장치 묶음

USB 분류 아래에는 장치 종류(키보드·저장 장치 등)별 노드가 있고, 그 아래에 엔진이 묶은 **물리 장치 후보**가 있습니다.
후보를 고르면 그 장치의 인터페이스·HID 자식·속성 시각 기록이 함께 보입니다. 묶음은 기록된 컨테이너 ID·부모 장치·VID/PID와 시리얼 같은
근거로만 만들어지며 같은 장치로 확정한 것은 아닙니다(표의 "물리 장치 묶음" 열에 근거 표시). 허브·컨트롤러는 "시스템 장치",
블루투스 서비스 항목은 "보조 항목"으로 따로 접혀 있습니다. 종류를 알 수 없는 장치는 "알 수 없는 이유" 열에 이유가 나옵니다.
(`tests/test_tree.py`가 분류 누락을 검사합니다).

## 분석자 태그와 메모

타임라인 행이나 파일 목록의 파일을 오른쪽 클릭해 **빨강 / 노랑 / 초록** 태그를 켜고 끄거나 메모를 남깁니다.
기본 이름은 빨강 "중요·확인 필요", 노랑 "검토 필요", 초록 "확인 완료"이고 **색 이름 바꾸기**로 바꿀 수 있습니다.
색마다 **새 하위 분류...**로 하위 분류(예: 빨강 › 유출 의심, 빨강 › 악성 의심)를 만들어 붙입니다. 색 이름과 하위 분류 목록은
사용자 설정 파일(`%APPDATA%\LogHunter\settings.json`)에 남아 다음 실행에도 쓰입니다.
태그한 기록은 타임라인에서 가장 급한 색(빨강 > 노랑 > 초록)의 연한 배경으로 보이고, 왼쪽 **분석자 태그**에서 색 › 하위 분류로 모아 봅니다.
**태그 불러오기**로 예전에 저장한 `case.sqlite`의 태그를 읽기 전용으로 다시 불러올 수 있으며, 색이 생기기 전의
"주목 / 추적 필요 / 정상으로 확인"은 각각 빨강 / 노랑 / 초록으로 바뀝니다.
태그는 분석자의 판단이므로 증거 데이터와 섞지 않습니다. 기록·파일은 바뀌지 않고, **보고서 저장** 때
`case.sqlite`의 별도 표 `examiner_tags`, `report.json`의 `examiner_tags`, `report.html`의 **분석자 태그** 탭에만 저장됩니다
(태그가 없으면 셋 다 생기지 않습니다). 기록의 태그는 기록 내용(종류·출처·위치·시각·경로 등)으로 찾으므로
같은 입력을 다시 분석해도 유지됩니다. 프로그램을 닫으면 저장하지 않은 태그는 사라집니다.

## 구현

- `log_hunter/core/tree.py`: GUI와 분리된 트리 모델. `build_tree()`, `matches()`(노드-기록 일치),
  `OriginIndex`(추출 사본 경로 → 이미지 안의 원래 경로), `event_properties()`(아래 기록 정보 창).
- `log_hunter/ui/` (화면):
  - `app.py`: 창·위젯 배치와 이벤트 연결, 작업 스레드(mailbox)
  - `view_model.py`: Tk 없이 테스트하는 데이터 쪽. 필터(`Filters`, `filter_events`), 타임라인 행, 빠른 검색, 개수·요약 문구, 연관·처리 결과·증거 행
  - `nav.py`: 왼쪽 트리 채우기, 노드 선택 시 동작 결정(`node_action`)
  - `detail.py`: 아래 기록 정보(항목/값 트리)와 원본 JSON 색칠
  - `charts.py`: 통계 탭 그림(비율, 상위 활동, 시간대, 처리 상태, 요일×시간)
  - `style.py`: 기록 종류별 색(모든 파서에 색이 있는지 테스트가 확인)
  - `columns.py`: 분류별 결과 표 열과 표 CSV 저장
  - `fs_model.py`: 이미지 파일 시스템 노드(볼륨·폴더·파일, 기록 수, 표시 상한), 파일 종류·파일 보기 분류, 파일 목록 표 모델(`FileTable`)
  - `file_list.py`: 파일 목록 탭(정렬·검색·페이지·오른쪽 클릭)
  - `content.py`: 파일 정보 행, 16진수 줄, 문자열 추출 / `jobs.py`: 작업 스레드 하나와 오래된 결과 버리기
- `log_hunter/core/tags.py`: 분석자 태그·메모 모델(`TagBook`), 기록·파일 식별 키, 트리의 분석자 태그 루트, `case.sqlite` 저장
- `log_hunter/image/browse.py`: 이미지·이 PC 드라이브를 읽기 전용으로 탐색(볼륨, 폴더, 파일 페이지 읽기)
- LOG1/LOG2로 복구한 하이브의 기록도 임시 복구 사본이 아니라 원래 하이브 아래에 보입니다.
